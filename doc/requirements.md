Система интеллектуального интервального повторения знаний

1. Описание проблемы

1.1. Проблема

В процессе обучения человек получает и фиксирует большое количество информации, однако сохранение материала в виде конспектов не обеспечивает его долговременного запоминания.

Основные проблемы:

Забывание информации. Без регулярного повторения человеку становится сложнее самостоятельно воспроизводить изученный материал.

Пассивное обучение. Перечитывание конспекта не требует обязательного воспроизведения знаний по памяти.

Недостаток обратной связи. При самостоятельном обучении трудно объективно определить полноту и правильность понимания темы.

Сложность планирования повторений. Пользователю необходимо самостоятельно контролировать сроки и периодичность возвращения к материалу.

Трудности устного объяснения. Человек может узнавать изученную информацию, но испытывать затруднения при её самостоятельном объяснении.

Низкое качество исходных материалов. Конспекты могут содержать ошибки, неоднозначности или недостаточно раскрытые понятия.

1.2. Цель

Создать приложение, которое помогает пользователю закреплять самостоятельно изученную информацию с помощью активного воспроизведения, автоматизированного оценивания знаний и интервального повторения.

Дополнительная цель — развитие способности самостоятельно и последовательно объяснять изученный материал.

1.3. Предлагаемое решение

Пользователь создаёт текстовый конспект, который служит основой для проверки знаний.

ИИ анализирует содержание конспекта, определяет возможность оценивания по нему и формирует проверочный контекст.

Пользователь воспроизводит изученный материал устно или, при поддержке соответствующего режима, текстом.

Голосовой ответ преобразуется в текст микросервисом транскрибации.

ИИ оценивает соответствие ответа проверочному контексту и возвращает результат в процентах, а также сведения о недостаточно раскрытых аспектах.

Backend использует результат оценивания для изменения расписания последующих повторений.

В перспективе приложение также предоставляет проверку достоверности конспектов через внешние источники, предложения по исправлению ошибок и интерактивный диалог с ИИ-экзаменатором.

2. Акторы системы

2.1. Пользователь

Основной актор приложения.

Возможности:

Создание и редактирование конспектов.

Запуск повторений.

Запись голосового ответа.

Получение оценки знаний.

Просмотр ошибок и недостаточно раскрытых аспектов.

Просмотр расписания.

Получение и настройка напоминаний.

Управление личными данными.

2.2. Внешний LLM-сервис

Внешняя система, обеспечивающая интеллектуальную обработку текста.

Функции:

Анализ достаточности и полноты конспекта для оценивания.

Формирование проверочного контекста.

Оценивание пользовательских ответов.

Выявление пропущенных или некорректно объяснённых аспектов.

Генерация вопросов и проведение диалога в расширенной версии.

2.3. Внешний поисковый сервис

Обеспечивает получение информации из интернета для проверки фактической достоверности конспектов.

Не используется в MVP.

2.4. Сервис доставки уведомлений

Обеспечивает передачу напоминаний выбранными пользователем способами.

Реализация и конкретный провайдер для MVP пока не определены.

2.5. Внутренние компоненты

В общую границу продукта входят:

Основной backend на Kotlin/Ktor.

Микросервис транскрибации на Python.

Хранилище конспектов и результатов.

Модуль управления расписанием повторений.

Модуль интеграции с LLM.

Эти компоненты не рассматриваются как самостоятельные внешние акторы при описании всей системы.

5. Бизнес-правила

5.1. Управление знаниями

BR-01. Пользователь самостоятельно определяет содержимое конспектов.

BR-02. В MVP система не осуществляет проверку фактической достоверности конспектов по внешним источникам.

BR-03. Анализ полноты конспекта в MVP направлен на определение возможности построить проверочный контекст, а не на проверку достоверности всех утверждений.

BR-04. Проверочный контекст формируется исключительно на основании содержания конспекта.

BR-05. LLM не должна добавлять в проверочный контекст обязательные для воспроизведения факты, отсутствующие в конспекте.

BR-06. Если конспект состоит из ключевых слов и не содержит достаточного материала для объективного оценивания, система должна предложить пользователю дополнить его.

BR-07. Изменение конспекта должно приводить к актуализации соответствующего проверочного контекста.

5.2. Оценивание

BR-08. Ответ пользователя оценивается относительно проверочного контекста, сформированного на основании конспекта.

BR-09. Оценка выставляется LLM в диапазоне от 0 до 100%.

BR-10. Оценка должна учитывать полноту раскрытия материала и содержательную корректность воспроизведённой информации.

BR-11. При оценивании допускается перефразирование: пользователь не обязан дословно воспроизводить конспект.

BR-12. Итоговая оценка должна сопровождаться указанием оснований оценивания.

BR-13. Результат оценивания сохраняется вместе с транскрипцией ответа.

BR-14. Ошибка технической обработки не должна интерпретироваться как недостаточное знание материала.

5.3. Интервальное повторение

BR-15. В MVP единицей повторения является целый конспект.

BR-16. После создания конспекта формируется первоначальное расписание повторений.

BR-17. Расписание формируется на основании заранее определённой последовательности возрастающих временных интервалов.

BR-18. Если пользователь выполнил повторение с задержкой, оставшиеся даты первоначально переносятся на количество дней просрочки.

BR-19. После учёта просрочки расписание дополнительно корректируется с учётом качества ответа пользователя.

BR-20. Качество ответа определяется на основании процентной оценки LLM и фиксированных пороговых значений.

BR-21. Низкая оценка должна приводить к более раннему повторению материала, высокая — к сохранению или увеличению интервала, согласно принятому алгоритму.

BR-22. При повторном расчёте расписания ранее выполненные повторения не изменяются.

BR-23. История оценок сохраняется независимо от изменения будущего расписания.

BR-24. Если пользователь прошёл проверку досрочно, система должна применить отдельно определённое правило пересчёта расписания; результат не должен создавать дублирующиеся обязательные повторения.

5.4. Уведомления

BR-25. Уведомления формируются на основании актуального расписания пользователя.

BR-26. Просроченное повторение сохраняет статус требующего выполнения до прохождения проверки либо другого предусмотренного пользовательского действия.

BR-27. После изменения расписания устаревшие уведомления не должны отправляться.

BR-28. Для уведомлений должны использоваться только выбранные пользователем и поддерживаемые системой каналы.

6. Ограничения

6.1. Технологические

C-01. Основной backend реализуется на Kotlin с использованием Ktor.

C-02. Транскрибация выполняется отдельным микросервисом на Python.

C-03. Для хранения основных данных используется PostgreSQL.

C-04. Для интеллектуального анализа и оценивания используется LLM API.

C-05. Алгоритм планирования повторений реализуется на backend и не зависит от LLM.

C-06. Для MVP не требуется внедрение брокеров сообщений или дополнительных специализированных микросервисов.

6.2. Ограничения MVP

C-07. Проверка фактической достоверности через интернет не реализуется.

C-08. Автоматическое исправление и дополнение конспектов не реализуется.

C-09. Конспект является единой единицей повторения; отдельные понятия не получают независимых расписаний.

C-10. Конспекты из одних ключевых слов без достаточных пояснений не поддерживаются как полноценная основа оценивания.

C-11. Оценивание выполняется по тексту ответа.

C-12. Анализ тембра, интонации, произношения, пауз и иных акустических характеристик речи не реализуется.

C-13. Просмотр и редактирование результата транскрибации перед оцениванием не предусматриваются.

C-14. Исходные аудиозаписи не хранятся после обработки.

C-15. Непрерывный двусторонний голосовой диалог в реальном времени не реализуется.

C-16. Пользователь воспроизводит материал по одному конспекту за одну проверку.

7. Границы MVP

7.1. Основной сценарий

Пользователь создаёт текстовый конспект.

Система сохраняет конспект.

LLM анализирует достаточность содержимого для проверки знаний.

При достаточном содержании LLM формирует проверочный контекст.

Система сохраняет проверочный контекст и формирует первоначальное расписание.

Пользователь начинает повторение.
